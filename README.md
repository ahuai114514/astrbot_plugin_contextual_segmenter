# astrbot_plugin_contextual_segmenter

该项目由 Codex 编写。

一个用于 AstrBot 的回复分条插件。它先执行硬保护判断；保护未命中时，已有换行会立即触发分条；没有可分换行时，再调用当前会话模型判断是否分条及分条边界。

## 功能概述

- 使用当前会话模型结合用户请求和回复语义，动态决定是否分条。
- 模型只返回句子编号分组，不改写、不增删原回复内容。
- 模型调用失败、超时或格式错误时，固定回退到本地语境判断。
- 自动选择合适的条目数，而不是固定切成同样的条数。
- 支持按用户输入关键词强制不分段。
- 支持按输出文本关键词强制不分段。
- 支持在硬保护未命中时按现有换行强制分条。
- 模型会结合语义判断作文、长文、代码块、引用和列表等内容是否适合分条。
- 会保留第一条为原消息，其余条目在原消息发送后自动补发。

## 执行优先级

插件当前的处理顺序如下，越靠前优先级越高：

1. 第一优先级：硬保护组
   输入禁用关键词、输出禁用关键词、结构化多行保护中任意一项命中，立即保持原文不分条，并停止全部后续判断。
2. 第二优先级：现有换行强制分条
   检测到至少两行非空文本时，立即按现有换行分条并停止后续判断；分条结果受最大条数限制。该优先级低于输入禁用词、输出禁用词和结构化多行保护。
3. 第三优先级：模型判断
   模型返回合法判断后，无论决定分条还是不分条，都立即采用结果并停止后续判断。
4. 后备本地判断
   只有模型关闭、调用失败、超时或返回格式无效时，才评估最短文本长度、本地语境规则和最大条数。

## 配置项

下面的配置顺序与实际执行优先级保持一致：

### 1. `enabled`

- 类型：`bool`
- 默认值：`true`
- 作用：总开关。关闭后插件不会修改任何回复。

### 2. `input_disable_keywords`

- 类型：`list[string]`
- 默认值：见下方“默认内置关键词”列表。
- 作用：命中用户输入文本后，强制不分条。
- 说明：这里检查的是 `event.message_str`，也就是用户当前发送的纯文本内容。

示例：

默认内置关键词：

```json
["作文", "写作", "简历", "个人介绍", "自我介绍", "个人简介", "怎么写", "结合教材", "展开讨论", "谈你的理解", "论述", "内在联系", "为什么说", "说明你的理由", "说说你的理由", "生活实际"]
```

你也可以在配置里继续追加自己的关键词。

### 3. `output_disable_keywords`

- 类型：`list[string]`
- 默认值：`["今日一言", "今日语录", "今日新闻", "Pixiv图片"]`
- 作用：命中机器人输出文本后，强制不分条。

示例：

```json
["作文", "演讲稿", "总结", "检讨"]
```

### 4. `protect_structured_multiline_output`

- 类型：`bool`
- 默认值：`true`
- 作用：保护会话信息、指标面板、字段列表这类结构化多行输出，避免被拆成一大串消息。

### 5. `structured_multiline_min_lines`

- 类型：`int`
- 默认值：`5`
- 作用：判定结构化多行输出时要求的最少非空行数。
- 说明：这是你要的修改入口，默认 `>= 5` 才会触发结构化多行保护。

### 6. `force_segment_on_newline`

- 类型：`bool`
- 默认值：`true`
- 作用：硬保护未命中时，检测现有换行并立即分条。
- 说明：至少需要两行非空文本；分条结果受 `max_paragraphs` 限制，模型不会覆盖换行分条结果。

### 7. `model_decision_enabled`

- 类型：`bool`
- 默认值：`true`
- 作用：使用当前会话正在使用的模型进行分条判断。
- 说明：每次符合前置条件的回复会额外产生一次模型调用。

### 8. `model_timeout_seconds`

- 类型：`float`
- 默认值：`10.0`
- 作用：限制模型分条判断的等待时间，最小按 1 秒执行。

### 9. `min_length_to_segment`

- 类型：`int`
- 默认值：`20`
- 作用：语境分条的最短长度门槛。
- 说明：低于这个长度时，通常不会触发语境分条。

### 10. `max_paragraphs`

- 类型：`int`
- 默认值：`3`
- 作用：限制语境分条最多拆成多少条。
- 说明：插件会动态决定条数，但不会超过这个值。

### 11. `send_delay_seconds`

- 类型：`float`
- 默认值：`0.8`
- 作用：多条消息之间的发送间隔。
- 说明：第一条补发紧随原消息发送；从第二条补发开始，按该值等待后再发送。

## 模型分条是怎么判断的

硬保护组未命中后，插件把用户当前请求和按编号切分的回复句子交给当前会话模型。模型只能决定是否分条，并返回连续的句子编号分组；插件会严格校验编号是否完整、有序且无重复，然后使用原句构建消息，因此模型无法改写回复。合法的模型判断会直接截断后续流程。

没有可分换行且模型判断失败时，默认联合使用最短长度、最大条数和以下本地启发式规则：

- 文本更长时，更容易分条。
- 句子更多时，更容易分条。
- 出现明显的话题切换词时，更容易分条。
- 出现编号或列表结构时，更容易分条。
- 像作文、文章、总结、检讨这类长文创作时，会降低分条倾向。
- 文本本身已有较多换行时，会降低语境分条倾向；正常情况下，已有换行会在进入模型前直接完成分条。

当前切句主要依据这些标点：

```text
。！？!?；;
```

## 默认保护场景

- 输入或输出命中配置的禁用关键词时，硬截断并保持原文。
- 结构化多行输出达到配置行数时，硬截断并保持原文。
- 作文、代码块、引用和列表等其他内容由模型优先判断；模型失败时再交给联合后备规则。

## 配置建议

如果你主要担心“写作文时被乱分条”，建议这样配：

```json
{
  "enabled": true,
  "input_disable_keywords": ["作文", "写作", "简历", "个人介绍", "自我介绍", "个人简介", "怎么写", "结合教材", "展开讨论", "谈你的理解", "论述", "内在联系", "为什么说", "说明你的理由", "说说你的理由", "生活实际", "读后感", "演讲稿"],
  "output_disable_keywords": ["今日一言", "今日语录", "今日新闻", "Pixiv图片", "作文", "演讲稿", "总结", "检讨"],
  "force_segment_on_newline": true,
  "model_decision_enabled": true,
  "model_timeout_seconds": 10.0,
  "min_length_to_segment": 20,
  "max_paragraphs": 3,
  "send_delay_seconds": 0.8
}
```

如果你更希望“模型只要自己换行了，就按它的结构发出去”，可以这样配：

```json
{
  "protect_structured_multiline_output": true,
  "structured_multiline_min_lines": 5,
  "force_segment_on_newline": true,
  "send_delay_seconds": 0.2
}
```

## 注意事项

- 这个插件目前只处理“只有一个 `Plain` 文本组件”的最终回复；带图片、文件、At 或多个混合组件的结果默认不拆条，以免破坏原消息结构。
- 模型判断会额外产生一次模型调用，并增加相应延迟和 token 消耗。
- 当前会话没有可用模型，或模型返回无效编号分组时，会固定回退到本地联合判断。
- 如果你后续想把“作文保护”“问答分条”“列表分条”拆成独立开关，也可以继续扩展。
- 结构化多行保护默认要求非空行数 `>= 5`，你可以通过 `structured_multiline_min_lines` 调整。
