# astrbot_plugin_contextual_segmenter

该项目由 Codex 编写。

一个用于 AstrBot 的回复分条插件。它不会简单按固定正则频繁拆条，而是先做保护规则判断，再优先尊重已有换行，最后才做语境分条，并把结果拆成多条独立消息发出去，尽量避免在作文、长文、代码块、列表等场景里错误拆条。

## 功能概述

- 根据回复内容的长度、句子数、话题切换和结构特征，动态决定是否分条。
- 自动选择合适的条目数，而不是固定切成同样的条数。
- 支持按用户输入关键词强制不分段。
- 支持按输出文本关键词强制不分段。
- 支持检测输出中的现有换行，并在语境分条之前优先按换行拆条。
- 自动保护作文、长文、代码块、引用、列表等内容，避免不该分条时乱拆。
- 会保留第一条为原消息，其余条目在原消息发送后自动补发。

## 执行优先级

插件当前的处理顺序如下，越靠前优先级越高：

1. 输入关键词禁用分条
   命中 `input_disable_keywords` 后，直接不分条。
2. 输出保护规则
   包括 `output_disable_keywords`、结构化多行输出保护、作文/长文特征、代码块、引用、列表等。命中后直接不分条。
3. 结构化多行输出保护
   当输出像字段面板、状态列表、仓库信息卡片这类结构化内容，且非空行数达到阈值时，不分条。
4. 现有换行强制分条
   如果开启 `force_segment_on_newline`，且输出中已经有换行，就优先按已有换行结构拆成多条消息。
5. 语境分条
   只有前面的规则都没有接管时，才按长度和结构特征做语境分条。
6. 保持原样
   以上都不触发时，不修改输出。

## 配置项

下面的配置顺序与实际执行优先级保持一致：

### 1. `enabled`

- 类型：`bool`
- 默认值：`true`
- 作用：总开关。关闭后插件不会修改任何回复。

### 2. `input_disable_keywords`

- 类型：`list[string]`
- 默认值：`[]`
- 作用：命中用户输入文本后，强制不分条。
- 说明：这里检查的是 `event.message_str`，也就是用户当前发送的纯文本内容。

示例：

默认内置关键词：

```json
["作文", "写作", "简历", "个人介绍", "自我介绍", "个人简介", "怎么写", "结合教材", "展开讨论", "谈你的理解", "论述", "内在联系", "为什么说"]
```

你也可以在配置里继续追加自己的关键词。

### 3. `output_disable_keywords`

- 类型：`list[string]`
- 默认值：`[]`
- 作用：命中机器人输出文本后，强制不分条。

示例：

```json
["作文", "演讲稿", "总结", "检讨"]
```

### 4. `force_segment_on_newline`

- 类型：`bool`
- 默认值：`true`
- 作用：检测到输出中存在换行时，优先按现有换行拆成多条消息。
- 说明：这个规则的优先级高于语境分条，低于输入关键词、输出关键词和结构化多行保护。

### 4. `protect_structured_multiline_output`

- 类型：`bool`
- 默认值：`true`
- 作用：保护会话信息、指标面板、字段列表这类结构化多行输出，避免被拆成一大串消息。

### 5. `structured_multiline_min_lines`

- 类型：`int`
- 默认值：`5`
- 作用：判定结构化多行输出时要求的最少非空行数。
- 说明：这是你要的修改入口，默认 `>= 5` 才会触发结构化多行保护。

### 6. `force_segment_on_newline`

- 类型：`bool`
- 默认值：`true`
- 作用：检测到输出中存在换行时，优先按现有换行拆成多条消息。
- 说明：这个规则的优先级高于语境分条，低于输入关键词、输出关键词和结构化多行保护。

### 7. `min_length_to_segment`

- 类型：`int`
- 默认值：`20`
- 作用：语境分条的最短长度门槛。
- 说明：低于这个长度时，通常不会触发语境分条。

### 8. `max_paragraphs`

- 类型：`int`
- 默认值：`4`
- 作用：限制语境分条最多拆成多少条。
- 说明：插件会动态决定条数，但不会超过这个值。

### 9. `send_delay_seconds`

- 类型：`float`
- 默认值：`0.4`
- 作用：多条消息之间的发送间隔。
- 说明：第一条会作为原消息发送，剩余条目会在原消息发出后按这个延迟依次补发。

## 语境分条是怎么判断的

插件不是调用大模型重新判断，而是使用一组启发式规则打分：

- 文本更长时，更容易分条。
- 句子更多时，更容易分条。
- 出现明显的话题切换词时，更容易分条。
- 出现编号或列表结构时，更容易分条。
- 像作文、文章、总结、检讨这类长文创作时，会降低分条倾向。
- 文本本身已有较多换行时，会降低语境分条倾向，优先把“已有结构”留给换行分条逻辑处理。

当前切句主要依据这些标点：

```text
。！？!?；;
```

## 默认保护场景

即使你没有配置关键词，下面这些情况也会尽量不分条：

- 作文、文章、散文、议论文、说明文、总结、报告、检讨、演讲稿等长文特征明显
- Markdown 代码块
- 行内代码
- 引用块
- 列表项
- 编号项

## 配置建议

如果你主要担心“写作文时被乱分条”，建议这样配：

```json
{
  "enabled": true,
  "input_disable_keywords": ["作文", "写作", "简历", "个人介绍", "自我介绍", "个人简介", "怎么写", "结合教材", "展开讨论", "谈你的理解", "论述", "内在联系", "为什么说", "读后感", "演讲稿"],
  "output_disable_keywords": ["作文", "演讲稿", "总结", "检讨"],
  "force_segment_on_newline": true,
  "min_length_to_segment": 20,
  "max_paragraphs": 4,
  "send_delay_seconds": 0.4
}
```

如果你更希望“模型只要自己换行了，就按它的结构发出去”，可以这样配：

```json
{
  "protect_structured_multiline_output": true,
  "structured_multiline_min_lines": 5,
  "force_segment_on_newline": true,
  "send_delay_seconds": 0.2
}
```

## 注意事项

- 这个插件目前只处理“只有一个 `Plain` 文本组件”的最终回复；带图片、文件、At 或多个混合组件的结果默认不拆条，以免破坏原消息结构。
- 语境分条属于启发式策略，不是语义理解模型，因此规则可以继续按你的使用习惯调整。
- 如果你后续想把“作文保护”“问答分条”“列表分条”拆成独立开关，也可以继续扩展。
- 结构化多行保护默认要求非空行数 `>= 5`，你可以通过 `structured_multiline_min_lines` 调整。
